# 批不变模式下的批量矩阵乘性能优化

## 背景

vLLM 在推理时支持"批不变"(batch-invariant)模式——无论输入请求如何分批,同一组请求的输出必须逐位相同。这一确定性保证对强化学习、A/B 测试和可复现评测至关重要。

当前实现中,批量矩阵乘(batched matrix multiply, BMM)在批不变模式下性能存在瓶颈。给定输入张量 A (B×M×K) 和 B (B×K×N),需要计算输出 C (B×M×N),其中 B 是批次维度。现有实现为保证批不变性采用了保守策略,在高批次、中等矩阵尺寸的场景下(例如 B=32, M=N=1280, K=5120)延迟较高。

## 任务

优化 `vllm/model_executor/layers/batch_invariant.py` 中的 `bmm_batch_invariant` 函数,在保持批不变性的前提下提升性能。

### 约束

1. **正确性硬门**:批不变性必须严格保持——对于任意输入,逐个处理(batch_size=1 循环 B 次)与批量处理(batch_size=B 一次)的输出必须逐位相同(bitwise identical)。
2. **兼容性**:保持函数签名不变,支持 bfloat16/float16/float32 三种数据类型。
3. **硬件**:优化目标为 NVIDIA H100/A100 GPU。

### 评测

- **正确性**:通过 `tests/v1/determinism/test_batch_invariance.py` 中的批不变性测试。
- **性能**:在标准形状集合(B∈{1,8,32}, M=N∈{512,1280,2048}, K∈{2560,5120})上测量延迟,相对基线的加速比作为性能得分。

## 提示

- 批不变性的核心:对同一组逻辑元素,无论如何分批,浮点运算的顺序和精度必须一致。
- GPU 编程中常见的性能优化手段(融合、并行、块调优)需要在不破坏上述顺序约束的前提下应用。

---
**注**:本任务源于 vLLM 项目在批不变性能力建设中识别的真实瓶颈。优化需在确定性与吞吐之间找到平衡点。
