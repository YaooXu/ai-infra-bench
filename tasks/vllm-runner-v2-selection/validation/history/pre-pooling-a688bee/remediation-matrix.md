This record supersedes the archived e575a2b verification claims. Current results are in e2e-evidence.json; a local Docker script run is not a Harbor trial.

| Problem | Change | Validation |
| --- | --- | --- |
| Redundant workspace instruction and hard-wrapped prose | Three natural paragraphs describing observable behavior | Statement inspection and semantic-boundary.md |
| Full-history download and incomplete generated runtime files | Exact shallow Base fetch; pinned FlashMLA interface added to native manifest | Fresh Docker build and final-image audit |

| Private field names, error keyword and validation placement rejected valid implementations | Grade constructed runner or failed startup with diagnostic | Renamed field, changed wording and delayed validation controls |
| Compatibility dimensions were missing | Add quantized/MoE/prompt-embedding/raw/processed-logits scenarios | Expanded positive and negative controls |
| Bundled alternatives were themselves incomplete | Preserve independent representations while completing compatibility checks | Both repaired alternatives and retained incomplete version |
| Repeated process startup inflated runtime | Reuse imports within each startup-override group, with separate processes for unset/0/1 and fresh worker/config per case | Per-case and per-implementation timings |
| Host test ownership and venv handling were unverified | Root staging and preservation of selected interpreter path | Non-root-owned mount with an actual /opt/venv interpreter |

The image and executable hashes are frozen for each local run. Runtime outcomes and limitations are reported without carrying forward older results as acceptance evidence.
